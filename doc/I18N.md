# bookkit — Multilingual support

Multilingual support is built into the format from the start, not bolted on. A
book has **one source language** and any number of translations. If you keep
only German and English today, you can add French, Spanish, … later without
restructuring existing books.

---

## 1. The model: parallel directories

Each language is its own directory with **identical file names**:

```
git-und-tcltk/        # source (lang = de)
git-und-tcltk-en/     # English translation
git-und-tcltk-fr/     # French translation
```

- Same chapter file names, same `book.tcl` structure (`chapters` in the same
  order).
- Only these differ: `lang`, `title`, `subtitle`, `tocTitle`, `indexTitle` —
  and of course the body text.
- The language code is ISO 639-1 (`de`, `en`, `fr`, `es`, …).

Each language is built separately:

```bash
tclsh bookkit/tools/book-build.tcl git-und-tcltk/    -number
tclsh bookkit/tools/book-build.tcl git-und-tcltk-en/ -number
```

Add a new language either with `book-new.tcl … -tr fr` at creation time, or by
copying the source directory and adjusting `book.tcl` (`lang`, titles).

---

## 2. What is translated — and what is not

**Body text** is translated. Left unchanged (from `SPEC.md` §3):

- Code blocks and inline `` `code` ``
- Commands, options, file names, paths, URLs, environment variables
- Established proper names

Comments **inside** code blocks may keep the source language.

`tocTitle` and `indexTitle` are set in the target language (the build knows
defaults for common languages; otherwise set them manually).

---

## 3. Glossary — multi-column

One glossary per book, all languages in a single file
(`glossary/<book-id>-glossary.tsv`):

```
de	en	fr
Erweiterung	extension	extension
Repository	repository	dépôt
```

New language = new column. A term appears exactly once (one row), not duplicated
per language pair. The glossary is a reference for translators and keeps
terminology consistent across languages.

---

## 4. Anchors across languages

The sore point of every translation: cross-references. A link
`[see X](#german-slug)` points at the slug of a **German** heading. Translate
the heading and the build produces a **different-language** slug — the copied
link breaks.

Solution: an **anchor map** per translation at
`i18n/<book-id>-anchors-<lang>.tsv`, format `source-slug⇥target-slug`:

```
# only TRANSLATED headings; omit identical slugs
grundlagen	fundamentals
bei-fehlern	when-things-go-wrong
```

Apply it to the translation directory:

```bash
tclsh bookkit/tools/i18n-fix-anchors.tcl git-und-tcltk-en/ i18n/git-und-tcltk-anchors-en.tsv
```

The tool rewrites only **link anchors** (`](#slug)`), never plain text, and
leaves slugs not in the map untouched (e.g. headings from proper names or code,
which stay the same anyway). Use `-n` for a dry run.

**How do I fill the map?** After the first build of both languages: for each
translated heading, add a row with the source slug (German) and the target slug
(translated). Headings that stay identical need no entry. `book-new.tcl` writes
a stub of the file.

---

## 5. Checking a translation

`i18n-check.tcl` scans a translation directory heuristically for **leftover
source language** — German body text still standing in the English version.
Code blocks, headings, inline code, Markdown links and URLs are skipped.
Index markers `[term]{.index}` are checked: a German term left in one
still counts.

```bash
tclsh bookkit/tools/i18n-check.tcl git-und-tcltk-en/
```

The heuristic is tuned for **German as the source language** (word list +
umlauts). For a different source language, swap the word list in the tool — that
is the **only** language-dependent place in the whole toolchain; everything else
is language-neutral.

---

## 6. Tracking translation status

The source book may run ahead of its translations. `i18n-status.tcl` keeps,
per translated chapter, a snapshot of the source chapter as it was when
translated, and reports per chapter `aktuell` / `veraltet` / `fehlt`;
`-diff <chapter>` shows what changed in the source since then, so only those
passages need translating. After translating: `-mark <chapter>`.

```bash
tclsh bookkit/tools/i18n-status.tcl book-tea/tea-de book-tea/tea-en
tclsh bookkit/tools/i18n-status.tcl book-tea/tea-de book-tea/tea-en -diff 020-die-bausteine.md
tclsh bookkit/tools/i18n-status.tcl book-tea/tea-de book-tea/tea-en -mark 020-die-bausteine.md
```

Storage: `i18n/<book-id>-sync-<lang>.tsv` and `i18n/<book-id>-sync-<lang>/`.
`REGISTRY.md` holds the coarse status per book and language. Details:
`TOOLS.md`.

---

## 7. Workflow for a new language (summary)

1. Create directory `<book-id>-<lang>/` (copy of the source, or via
   `book-new … -tr <lang>`).
2. Adjust `book.tcl`: `lang`, `title`, `tocTitle`, `indexTitle`.
3. Translate body text; leave code/commands/proper names unchanged.
4. Fill the glossary column `<lang>`.
5. Build; fill the anchor map `i18n/<book-id>-anchors-<lang>.tsv`; run
   `i18n-fix-anchors.tcl`.
6. Run `i18n-check.tcl` against leftovers; add an entry to `REGISTRY.md`.
