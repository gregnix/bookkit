# bookkit — Mehrsprachigkeit

Mehrsprachigkeit steckt von Anfang an im Format. Ein Buch hat **eine
Quellsprache** und beliebig viele Übersetzungen. Wer heute nur Deutsch und
Englisch führt, kann später Französisch, Spanisch und weitere Sprachen
ergänzen, ohne vorhandene Bücher umzubauen.

---

## 1. Das Modell: parallele Verzeichnisse

Jede Sprache ist ein eigenes Verzeichnis mit **denselben Dateinamen**:

```
git-und-tcltk/        # Quelle (lang = de)
git-und-tcltk-en/     # englische Übersetzung
git-und-tcltk-fr/     # französische Übersetzung
```

- Dieselben Kapiteldateien, dieselbe `book.tcl`-Struktur (`chapters` in
  derselben Reihenfolge).
- Es unterscheiden sich nur: `lang`, `title`, `subtitle`, `tocTitle`,
  `indexTitle` — und der Fließtext.
- Der Sprachcode ist ISO 639-1 (`de`, `en`, `fr`, `es`, …).

Jede Sprache wird einzeln gebaut:

```bash
tclsh bookkit/tools/book-build.tcl git-und-tcltk/    -number
tclsh bookkit/tools/book-build.tcl git-und-tcltk-en/ -number
```

Eine neue Sprache entsteht entweder beim Anlegen mit `book-new.tcl … -tr fr`
oder durch Kopieren des Quellverzeichnisses und Anpassen von `book.tcl`
(`lang`, Titel).

---

## 2. Was übersetzt wird — und was nicht

**Fließtext** wird übersetzt. Unverändert bleiben (aus `SPEC.md` §3):

- Code-Blöcke und Inline-`` `code` ``
- Befehle, Optionen, Dateinamen, Pfade, URLs, Umgebungsvariablen
- Etablierte Eigennamen

Kommentare **innerhalb** von Code-Blöcken dürfen die Quellsprache behalten.

`tocTitle` und `indexTitle` stehen in der Zielsprache (der Build kennt
Vorgaben für gängige Sprachen; sonst von Hand setzen).

---

## 3. Glossar — mehrspaltig

Ein Glossar je Buch, alle Sprachen in einer Datei
(`glossary/<book-id>-glossary.tsv`):

```
de	en	fr
Erweiterung	extension	extension
Repository	repository	dépôt
```

Neue Sprache = neue Spalte. Ein Begriff steht genau einmal (eine Zeile), nicht
je Sprachpaar doppelt. Das Glossar ist die Referenz für Übersetzer und hält
die Begriffe über die Sprachen gleich.

---

## 4. Anker über Sprachgrenzen

Der wunde Punkt jeder Übersetzung sind die Querverweise. Ein Link
`[siehe X](#deutscher-slug)` zeigt auf den Slug einer **deutschen**
Überschrift. Wird die Überschrift übersetzt, erzeugt der Build einen Slug in
der **anderen Sprache** — der mitkopierte Link bricht.

Lösung: eine **Anker-Map** je Übersetzung unter
`i18n/<book-id>-anchors-<lang>.tsv`, Format `quell-slug⇥ziel-slug`:

```
# nur ÜBERSETZTE Überschriften; gleiche Slugs weglassen
grundlagen	fundamentals
bei-fehlern	when-things-go-wrong
```

Auf das Übersetzungsverzeichnis anwenden:

```bash
tclsh bookkit/tools/i18n-fix-anchors.tcl git-und-tcltk-en/ i18n/git-und-tcltk-anchors-en.tsv
```

Das Werkzeug schreibt nur **Link-Anker** um (`](#slug)`), nie den Fließtext,
und lässt Slugs aus, die nicht in der Map stehen (etwa Überschriften aus
Eigennamen oder Code, die ohnehin gleich bleiben). `-n` ist der Probelauf.

**Wie füllt man die Map?** Nach dem ersten Bau beider Sprachen: je übersetzter
Überschrift eine Zeile mit dem Quell-Slug (deutsch) und dem Ziel-Slug
(übersetzt). Überschriften, die gleich bleiben, brauchen keinen Eintrag.
`book-new.tcl` legt eine Stub-Datei an.

---

## 5. Eine Übersetzung prüfen

`i18n-check.tcl` sucht in einem Übersetzungsverzeichnis heuristisch nach
**stehen gebliebener Quellsprache** — deutscher Fließtext in der englischen
Fassung. Code-Blöcke, Überschriften, Inline-Code, Markdown-Links und URLs
werden übersprungen. Indexmarken `[begriff]{.index}` prüft es mit: ein
deutscher Begriff darin zählt.

```bash
tclsh bookkit/tools/i18n-check.tcl git-und-tcltk-en/
```

Die Heuristik ist auf **Deutsch als Quellsprache** eingestellt (Wortliste plus
Umlaute). Für eine andere Quellsprache wird die Wortliste im Werkzeug
getauscht — das ist die **einzige** sprachabhängige Stelle der ganzen
Werkzeugkette; alles andere ist sprachneutral.

---

## 6. Übersetzungsstand führen

Das Quellbuch darf den Übersetzungen vorauslaufen. `i18n-status.tcl` hält je
übersetztem Kapitel eine Aufnahme des Quellkapitels fest, wie es bei der
Übersetzung war, und meldet je Kapitel `aktuell`, `veraltet` oder `fehlt`.
`-diff <kapitel>` zeigt, was sich in der Quelle seither geändert hat; nur
diese Stellen müssen nachgezogen werden. Nach dem Nachziehen: `-mark
<kapitel>`.

```bash
tclsh bookkit/tools/i18n-status.tcl book-tea/tea-de book-tea/tea-en
tclsh bookkit/tools/i18n-status.tcl book-tea/tea-de book-tea/tea-en -diff 020-die-bausteine.md
tclsh bookkit/tools/i18n-status.tcl book-tea/tea-de book-tea/tea-en -mark 020-die-bausteine.md
```

Ablage: `i18n/<book-id>-sync-<lang>.tsv` und `i18n/<book-id>-sync-<lang>/`.
`REGISTRY.md` hält den groben Stand je Buch und Sprache. Einzelheiten:
`TOOLS.md`.

---

## 7. Ablauf für eine neue Sprache

1. Verzeichnis `<book-id>-<lang>/` anlegen (Kopie der Quelle, oder über
   `book-new … -tr <lang>`).
2. `book.tcl` anpassen: `lang`, `title`, `tocTitle`, `indexTitle`.
3. Fließtext übersetzen; Code, Befehle und Eigennamen unverändert lassen.
4. Die Glossarspalte `<lang>` füllen.
5. Bauen; die Anker-Map `i18n/<book-id>-anchors-<lang>.tsv` füllen;
   `i18n-fix-anchors.tcl` laufen lassen.
6. `i18n-check.tcl` gegen Reste laufen lassen; einen Eintrag in `REGISTRY.md`
   ergänzen.
